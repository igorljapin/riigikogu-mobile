Shipping the Crown icon

igorljapin/riigikogu-mobile · both surfaces · 2026-08-24

Replacing the illustrated Toompea icon with the Crown mark on both installed apps. Everything you need is already generated in export/; the work is copying files in, running one script, and editing four files. No new dependencies, no build step added.

The whole job, in order

  1. Copy 7 SVG masters into icons/ and 1 script into scripts/
  2. Run node scripts/generate_icons.mjs — writes 10 PNGs
  3. Replace the icons array in manifest.json
  4. Replace the icons array in desktop/manifest.json
  5. Point two <link> tags in desktop/index.html at the new files
  6. Bump CACHE_NAME to v7 and update the precache list
  7. npm test, then install both apps and look at them

Before you start

You need Node and the repo's dev dependencies. sharp is already in package.json — it is what renders the PNGs, and nothing new gets added.

git checkout -b icon/crown
npm ci

Step 1 — Copy the files in

Seven SVG masters go into icons/, alongside the PNGs they will produce. The old icon.svg is overwritten; keep it in git history rather than renaming it.

icons/icon.svg                     mobile, light, rounded corners
icons/icon-dark.svg                mobile, dark theme
icons/icon-mono.svg                mobile, white on transparent
icons/icon-maskable.svg            mobile, square, 80% safe zone
icons/desktop-icon.svg             desktop, light, rounded corners
icons/desktop-icon-dark.svg        desktop, dark theme
icons/desktop-icon-maskable.svg    desktop, square, 80% safe zone
scripts/generate_icons.mjs         the PNG renderer

Why four masters per surface rather than one: the rounded file is what a browser shows as a favicon and what Windows puts on the taskbar, so it carries its own corner radius. The maskable file is square and full-bleed because Android and iOS apply their own mask on top, and a pre-rounded icon inside a mask gets rounded twice. Dark and mono are not loaded by the apps today — see the last section.

Step 2 — Generate the PNGs

node scripts/generate_icons.mjs

Step 5 — the two shells

The mobile index.html needs no change: it already points at ./icons/icon.svg and ./icons/apple-touch-icon.png, and both filenames are reused.

In desktop/index.html, change the two icon links so the desktop app stops borrowing the mobile mark:

- <link rel="icon" href="../icons/icon.svg" type="image/svg+xml">
- <link rel="apple-touch-icon" href="../icons/apple-touch-icon.png">
+ <link rel="icon" href="../icons/desktop-icon.svg" type="image/svg+xml">
+ <link rel="apple-touch-icon" href="../icons/desktop-apple-touch-icon.png">

Step 6 — the service worker

Two edits in service-worker.js. The cache name bump is what evicts the old icon from everyone who already installed the app; without it a returning visitor keeps the castle until their second visit.

- const CACHE_NAME = 'riigikogu-mobile-v6';
+ const CACHE_NAME = 'riigikogu-mobile-v7';

Then replace the four icon lines at the end of PRECACHE_ASSETS with the list below.

  './icons/icon.svg',
  './icons/icon-mono.svg',

  './icons/icon-512x512.png',
  './icons/icon-maskable-512.png',
  './icons/apple-touch-icon.png',

  './icons/desktop-icon.svg',
  './icons/desktop-icon-44.png',
  './icons/desktop-icon-192.png',

  './icons/desktop-icon-512.png',
  './icons/desktop-icon-maskable-512.png',
  './icons/desktop-apple-touch-icon.png',

List only files that actually exist. Install is deliberately allowed to fail loudly in this worker, so one missing entry rejects addAll() and kills registration for everyone. The four masters that nothing loads at runtime — icon-dark.svg, icon-maskable.svg and their desktop pairs — stay out of the list on purpose.

Step 7 — Check it

npm test          # 64 unit + 46 resolver + 118 Playwright
npm run serve     # http://localhost:8099

Then look at it on real hardware, because this is the one change no test can grade:

  • iPhone. Safari → Share → Add to Home Screen. Check the crown is not clipped by the corner mask and that the flag still reads at arm's length.
  • Windows 11. Edge → install the desktop app. Check the taskbar, the Start tile, and Alt-Tab — the 44px render is the one that fails first.
  • Android. Chrome → Install app. The maskable file is what you are checking here; the circle mask crops hard.
  • Browser tab. The favicon at 16px is the smallest the mark is ever asked to be.

An installed PWA caches its icon aggressively. To see a change on a device that already has the app, uninstall it, hard-reload the page, then re-install.

What iOS will and will not use

Worth knowing before you go looking for the dark and tinted versions on your phone. A home-screen web app on iOS reads only apple-touch-icon.png. It ignores the manifest's icon array, ignores purpose: maskable and monochrome, and has no mechanism for the dark, tinted or clear appearances at all — those belong to native apps, which declare them in an icon asset compiled by Xcode.

So the light mark is what ships to iPhone today. icon-dark.svg and icon-mono.svg are in the repo because they cost nothing to keep and they are the starting artwork the day you wrap either surface as a native app. icon-mono.svg does earn its keep now: Windows and Android both read purpose: monochrome for notification badges and themed icons.

Windows applies no corner rounding of its own to an installed PWA's icon, which is why desktop-icon.svg carries a 230/1024 radius baked in and the maskable file does not.

Changing the artwork later

Every colour in the masters is a token from styles.css: ground #0f172a, stone #f4f6f8, shadow face #94a3b8, flag blue #2563eb, flag dark #233046. The dark master swaps to #080d16 / #f6f8fb / #64748b. If a future redesign moves those tokens, the icons move with them by search and replace.

Two constraints to hold on to if you edit the geometry. The shaft must keep running off the bottom edge — the crop is what stops the mark reading as a generic tower. And the maskable master scales the whole drawing to 80% about the bottom centre, not the centre, so the crown moves inside the safe circle while the shaft stays flush; scale about the centre instead and a light band appears under the tower on Android.

Re-run node scripts/generate_icons.mjs and bump CACHE_NAME after any edit. Those two steps are the whole maintenance story.
